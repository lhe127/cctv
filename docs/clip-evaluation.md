# Local clip regression check

Run `python scripts/evaluate_clips.py` from the project root after placing `climbing-video.mp4`, `open-door-video.mp4`, and `door-tampering-video.mp4` in the ignored `media/test-clips/` folder and installing the YOLOX model. The files are not part of source control. The owner supplied these local copies; source pages appear to be [Pexels climbing footage](https://www.pexels.com/video/people-climbing-a-metal-fence-5244404/), [Pexels garage-door footage](https://www.pexels.com/video/woman-opening-the-garage-5221403/), and [Mixkit lock-tool footage](https://mixkit.co/free-stock-video/mugger-opening-the-lock-at-night-31380/). Their use remains subject to the applicable [Pexels](https://www.pexels.com/license/) and [Mixkit](https://mixkit.co/license/modal/videoFree/) licenses.

The climbing check uses sampled video seconds 0–33, with manually inspected climbing moments near 8–14 and 26–32 seconds. A broad wall zone and a horizontal crossing line at normalized `y=0.7` are specific to this demonstration view. The script reports how many of those two labeled windows contain an A07 alert. Other activity in the montage is not labeled, so alerts outside those windows are not scored as false positives.

The ordinary door-opening clip is a negative A08 example across its full 10.9 seconds. The staged lock-tool clip is a positive example, with repeated work at the lock near 6–9 seconds. Both use a small zone around the visible handle or lock, `activity_threshold=0.5`, `dwell_seconds=0.4`, and `min_activity_samples=2`. These are demonstration thresholds; the webcam example remains more conservative. The script reports any alerts on the ordinary clip as false positives and checks for an alert during the lock-tool window. Sampling uses video timestamps; live workers use wall-clock event timestamps. This limited check cannot establish sensitivity, specificity, or readiness for a different camera angle.
